### Setup B + no-claim baseline lock-in (§5.1)
Two experimental setups were on the table:
- **Setup A** — AI plays the role via system prompt ("You are a treating psychiatrist…"). Tests whether the model's *behavior in role* matches the standard.
- **Setup B** — AI serves a user who claims a role ("I am a treating psychiatrist…"). Tests whether the model's *response to a role-claiming user* is calibrated to that role's professional standard.

Phase 1 commits to **Setup B + a no-claim baseline**. Three reasons:

1. **Deployment-volume mismatch** — Setup B is the dominant deployment shape. End users approach LLMs claiming roles; AI rarely runs as a fully-instantiated forensic evaluator.
2. **Standard-bleed observability** — Setup B produces directly observable bleed: when the model responds to a role-claiming user with content from another profession's standard, the bleed is in the response. Setup A's bleed would have to be inferred from system-prompt-conditioned behavior, which is harder to attribute.
3. **Verified-literature gap** — both Liang 2510.24677 and the verified role-eval cluster operate in Setup-A territory. Setup-B + baseline is comparatively under-studied; the verified gap analysis specifically supports it.

Setup A is **deferred to Phase 2** as a cross-configuration comparison. Documented explicitly in §5.7.

### Rubric origin: hybrid inheritance + author-drafted with statute traceability
Resolved across two conversations: (a) does AI safety prefer LLM-only or human-authored rubrics, (b) can existing professional-domain evals be inherited from? Decision:

- **Inherit where possible** from CTRS, MISC, Beidas CBT Fidelity Scale, NASW Code of Ethics, ABA Model Code of Judicial Conduct, NYPD Patrol Guide §216-05, CounselBench rubric items, MHSafeEval taxonomy.
- **Author-draft the gaps** with explicit statute / professional-code citations per item (validity-by-construction: items source-traceable to authoritative text).
- **LLM-assisted drafting is permitted**; LLM as final authority is not. Workflow: cross-family LLM ensemble drafts → author curates → light expert face-validity review (1 expert per role, async, asynchronous-async-OK).
- **Cross-family ensemble** required to avoid same-family circularity: GPT, Claude, Llama draft independently; keep items at least two propose. Specifically prevents the failure mode where Claude-judges score a Claude-drafted rubric well by latent-style match.
- Phase 1 scope: **statute-traceability is the validity claim**, not full expert validation. Full expert validation is Phase 2 / paper-revision work.
