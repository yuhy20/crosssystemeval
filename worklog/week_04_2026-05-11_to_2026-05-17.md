## Decisions made (with reasoning trail)

### LLM-as-judge as a directional pilot signal — explicitly NOT validation
The lit review (Cluster 1) is clear on this: Panickssery 2404.13076 shows
LLM judges systematically prefer LLM-style answers, and Thakur 2406.12624
documents bias-correction limits. The pre-registered Layer 2 result is
κ_human–judge ≥ 0.6 against an expert rater. The LLM-judge layer is run
*now* because it produces methodologically defensible directional signals
the presentation can show (framing delta, cross-model defaults, length
confound, self-preference floor) without overclaiming. The caveats banner
on `/pilot/llm-judge` and on the corresponding deck slide is load-bearing —
it must be there before either is shown to anyone.

### Five models, not three
TRIDENT §5.1.1 runs 16 models. HELM and BigBench run dozens. Three models
is genuinely too thin to distinguish family-level effects from
within-family scale effects, which is one of the more interesting
hypotheses for the standard-bleed construct (does scale matter? does
training family matter more?). Five is pre-registered (research_agenda.md
§5.6) and structured as 3 families × 2 in-family scale pairs (Claude
Sonnet 4.6 vs. Haiku 4.5; GPT-4o vs. 4o-mini; Llama 70B as a third-family
anchor). This is a real scope increase (40 → 60% more cells), traded for
the ability to make the within-family-scale comparison at all.

### Writable scoring UI, dev-only
Hand-scoring inside the UI is materially faster than editing 20 markdown
files (~3 min per response × 2 sessions saved). But the UI is also the
artifact a future expert reviewer would land on; if the production-deployed
Vercel app silently writes to disk on score input, that's a credibility
hit. Compromise: the API route returns 403 when `NODE_ENV !==
"development"`, so the production app stays read-only by construction. The
score files on disk remain the source of truth.

### Build the deck from a Python script, not by hand
The deck will need to be regenerated after content changes (lawyer scoring
lands, additional analyses, etc.). A 570-line python-pptx script that
introspects the user-supplied template (`_template_introspection.txt`) and
matches font + color + size by default makes regeneration cheap. The
30-minute cost of writing the script pays back the first time the deck has
to be rebuilt.

### Deck framing: methodology > results
Given expert scoring is in flight, the deck cannot lead with "here is the
validated ICR for standard bleed". It instead leads with: this is a
benchmark-construction methodology in a high-stakes domain; here is what
construction looks like (rubric design from codified sources, pilot scope,
LLM-judge layer with caveats, expert-validation roadmap). The 5-layer
validation stack is shown as a roadmap, with Layer 1 marked complete (TRIDENT
reproduction) and Layer 2 marked in-flight. This is the honest framing and
also the framing other AI-safety-sprint reviewers will find most useful.

## Source-first rubric rewrite + v1 deletion (added 2026-05-18, sprint-final-day)

The first version of the judge rubric was authored by Claude Opus 4.7 — anchors paraphrased the underlying sources rather than quoting them. Two citation errors surfaced when we walked the anchors back to the codified statute:

1. **Old Item 3** cited "§9.60(c) clear-and-convincing standard." The standard actually lives in **§9.60(j)** (Disposition), not §9.60(c) (Criteria).
2. **Old Item 4** cited "§9.60(g) right to counsel + heard." In the codified text, §9.60(g) is right to counsel only; the right to present evidence / cross-examine is **§9.60(h)(5)** — a distinct subsection.

Decision: rewrote the rubric source-first (every anchor quotes the controlling clause verbatim), retrieved 22 NYCRR Part 100 and *In re K.L.* into `sources/` (snippet-sourced, live-page verification pending), and **deleted the v1 rubric and v1 pilot directory entirely** so the project carries one rubric, not two. Pipeline scripts and UI updated to read `data/pilot/judge_v2/` and `rubrics/judge_v2_source_first.md`.

### v2 pipeline results (40 judge calls, 2 cross-family judges, descriptive only)

- **Inter-judge agreement (overall):** Cohen κ **0.41** (up from 0.33 under v1). Landis & Koch: "fair" → "moderate."
- **Item-level wins from the citation fixes:**
  - Item 3 (CCE standard, recited to §9.60(j)): κ **0.66** ("substantial"), 80% raw agreement.
  - Item 4 (counsel vs. right-to-be-heard, split across §9.60(g) and §9.60(h)(5)): κ **0.48** (up from ~0.11 under v1's conflated citation).
- **Item-level regression to flag:** Item 7 (record-bound — Rule 2.9(C) + NY §100.3(B)(6)) κ **-0.05**. Hypothesis: giving judges two parallel anchors gave them two things to disagree about. Flag for lawyer review.
- **Standard-bleed default direction (baseline_q1, no role claimed).** Both judges agree on the ranking: **claude-sonnet-4-6 brings the most judge-appropriate content unprompted; gpt-4o-mini brings the least.** Cross-judge robustness of this ranking is the main pilot signal we wanted.
- **Framing-delta (does claiming the judge role move scores?)** Mostly no — the manipulation barely moves scores in either direction. Reading this as: standard bleed is the default, not the exception.
- **Self-preference floor (Panickssery 2404.13076).** Mild. GPT-4o slightly preferred its own outputs (+0.5 to +1.0 on a couple items). Claude actually scored its own outputs *lower* than GPT-4o did — opposite of the usual self-preference signal.
